The IMF tools and a reproducible pipeline

PEFA Converter, I2A, and the same logic in open code

Renato Vargas
Achille Pegoue

What this presentation covers

  1. The two IMF tools: what they take in, what they do, what they give back.
  2. Why the same logic was rewritten as an open, reproducible pipeline.
  3. How the pipeline is organised, how it checks itself, and how to run it.

The IMF tools

Why tools?

  • Compiling accounts from a balance and an inventory means hundreds of correspondence decisions.
  • A tool fixes the sequence of steps and applies the international recommendations the same way in every country.
  • The IMF Statistics Department developed two Excel tools with Python functions, written by Achille Pegoue (Pegoue, 2026b, 2026a).

PEFA Converter

  • Converts an energy balance in the IEA layout into physical supply and use tables for energy (International Monetary Fund, 2024).
  • Inputs, as named ranges of the workbook:
    • the balance (flows × products, in terajoules);
    • the concordance matrix: for each flow and product, the activity, the PEFA product, the table and the share;
    • bridging items for residence;
    • a classification of products (renewable, waste).
  • Output: a long table by PEFA product, activity and table, in petajoules.

Air Emissions Account Converter (I2A)

  • Converts a greenhouse gas inventory into air emissions accounts by activity and households (International Monetary Fund, 2026).
  • Inputs:
    • the inventory by gas, category and year;
    • the conversion matrix: for each category, the share of each activity;
    • the list of activities and bridging items;
    • OECD estimates of air and maritime transport emissions, for residence.
  • Output: emissions by gas, category and activity, with totals and bridging items.

How the tools work

From workbook to pipeline

Why rewrite the logic?

  • A workbook hides decisions in cells; a lookup table with a reason per row shows them.
  • Each year needs the same steps again: a pipeline repeats them in under a minute.
  • Checks run every time, and a failed check stops the run.
  • The same code writes the accounts in English, French and Arabic.
  • Anyone can read, rerun and challenge every number.

Two layers that must agree

  • Explicit layer: every rule of the tools rewritten step by step in readable Python. This produces the accounts.
  • Reference layer: the original tool functions, called unchanged, on the same inputs.
  • The run stops if the two differ:
    • energy accounts: largest gap 5e-13 PJ, all years and matrices;
    • emissions accounts: largest gap 7e-12 kt CO2 eq.

What a run produces

  • Excel workbooks in three languages, in the layout of the tool sheets.
  • Tidy tables with stable codes, and label tables in three languages.
  • Methods documents and slides whose numbers are read from those tables.
  • A data explorer on the website.

Running it

uv sync                                  # install Python and the packages
uv run python scripts/run_pipeline.py    # compile both accounts
bash scripts/render.sh                   # render the website

Rendering only reads the outputs: changing a sentence never requires recomputing.
